# 现状与求助

> 一个人把「共享浮空岛大世界」做到 v3.1.3，线上能打开了，但注册链路、托管形态和内容安全这几件事我判断不了了。**我已经没辙了**，所以把代码脱敏公开，求大佬帮忙看看有什么问题。
>
> 这不是求夸，是求挑错。下面写的数字都是实测或读代码得到的，跑不起来的地方我也照实写。

## 1. 我已经没辙了

这个项目从 11 月初一个人做到现在，中间推翻过一次整套方案（做过一版作品画廊，发现不对，整个撤掉了），又重做成现在的云海群岛。目前能确定的是：画面能跑、构图不重叠、静止时性能契约守得住、源码已经脱敏公开。

但我卡在三个地方，自己兜不住了：

- **注册/账号这条链路**：前端曾经把后端地址写死成另一个站点的，注册报「网络不通」；后来改成同源、建了表和函数，接口现在能返回正常 JSON，但**邮箱验证码的端到端收发我没实测过**，也不敢说注册已经好了。
- **托管形态**：现在跑在平台捆绑的云服务上，有月度额度、用尽自动暂停、域名和登录强绑定、还关不掉后端。我不知道现在该不该迁走、迁走要按什么顺序做。
- **让陌生人上传任意 HTML** 这件事本身的安全边界：沙箱、限流、审核、隔离域，我知道都缺，但缺到什么程度、先补哪个，我判断不了。

试过的事：读过浏览器控制台、用无头浏览器实载、写过构图验收脚本、把配置和代码脱敏了一遍。没定位到根因的是「注册链路到底还差哪一层」和「托管该不该现在换」。所以把仓库公开，请懂的人看一眼。

## 2. 这个项目是什么

一片 Three.js 云海，很多座岛浮在上面。**每座岛是创作者自己写的一个单文件 HTML 作品**——岛上长什么样完全由作者的代码决定，平台只负责云海、光照、时辰、取景，以及把大家的岛摆到一起。

打开页面：中心是当前焦点岛，周围是同批取景里的邻居。拖动可以环视、滚轮远近，点远处一座岛会「渡云」飞过去把它变成新焦点，右上角 `↻` 会重新洗一批岛。

一些真实数字：

| 项 | 值 |
|---|---|
| 主页面 | 单文件 `index.html`，286,603 B / 6356 行，HTML+CSS+JS 全内联 |
| 同屏岛数 | `ISLE_COUNT = 11`（上限 `MAX_VISIBLE = 15`、`MAX_SLOT = 16`、`MAX_CUBE = 420`） |
| 中心岛 | 从 580px（屏宽 36%）缩到约 317px（22%），给周围岛让出空间 |
| 活体 iframe | **恒为 1 座**（焦点岛能点能玩），其余是 3D 体素岛（岩体 / 岛顶 / 方块 / 灯笼 + 三档 LOD） |
| 构图验收 | 6 套模板 × 200 次抖动 = 1200 用例，0 重叠 / 0 出屏，最紧间距比 1.019 |
| 静止性能 | `?perf=1` 下 `0 style/s`、`0 resize/s`（相机静止整段跳过、iframe 尺寸 13 档量化、位移/透明度死区） |
| 上传约束 | 单个全内联 HTML、≤ 2 MB、禁止外链；`blob:` URL 绝不拼查询参数 |
| 缓存 | 正文走 IndexedDB + blob LRU，上限 4 座；换岛动效 620ms |
| 相机 | 绕转 + 受限平移（水平半径 ≤ 5.5、垂直 ±2.2、距离 9.5~24.5），云墙半径 22 |

三座内置作品是蓬莱仙境、古树、飞行空中堡垒，各自内联了渲染核心，所以离线也能跑。

## 3. 做到哪一步 / 卡在哪

现在有两条版本线，别混：

- **主线 `v3.1.3`**：带完整云端能力（注册、上传、留言、点赞、私信），后端是 6 张表 + 16 个 `SECURITY DEFINER` 函数 + RLS，目前**没有真实用户数据**。古树黑屏（原本动态加载 three.js，被分享码门禁挡住）已修成整包内联；注册所需的后端配置已改成与部署同源。接口做过一次只读实测，返回 `200` 且数据结构正常。
- **这个公开仓库 `open-0.1.0`**：是从主线派生的**脱敏离线快照**，`config.js` 三个值全空、`FI_OFFLINE = true`、`rpc()` 直接短路，**零网络请求**。账号、上传、留言在这里刻意用不了，也复现不了线上那条链路。

所以卡点很具体：**这个仓库能看到画面和代码，但看不到注册；另有一份接入托管后端的线上部署，地址与分享码不在公开仓库披露**（原因见 `SECURITY.md`）。想帮忙看注册问题的话，我可以私下提供访问方式。

明确未验证项：**邮箱验证码的端到端收发没有实测**，不宣称注册已经修好。

## 4. 已知缺陷

完整清单在 [`ASSESSMENT.md`](ASSESSMENT.md)：安全 7 条 / 架构 8 条 / 运维 4 条，共 19 条，按 P0/P1/P2 排了优先级和验收数字。这里只点最要命的几条：

- **A2（实测）**：受信任的 iframe 同时给了 `allow-scripts` 和 `allow-same-origin`，而用户上传的 HTML 走 `blob:` 会继承父源。无头 Chromium 直接打印 `An iframe which has both allow-scripts and allow-same-origin ... can escape its sandboxing.`。公开演示版不接收上传所以没入口，但代码缺陷在。
- **A3 / A4 / A5**：同源 iframe 与主文档共享渲染进程，一段死循环冻结整个标签页且看门狗一起死；写接口对匿名角色开放、无限流；`fi_island_add` 允许匿名上传任意 HTML 全文，没有审核。
- **B1 / B2**：世界快照一次返回全部作品元数据，无分页；HTML 正文按需拉取但没有服务端大小上限与缓存策略。
- **B6**：三座内置岛各内联一份 three.js（940,047 / 918,076 / 855,342 B），首屏潜在约 2.7 MB。
- **C3**：403 / 501 / 超时 / 无 SDK 全被压成一句「网络不通」，排查时根本分不出是哪一种。

## 5. 求大佬看的 8 个问题

每条都带编号、数字、复现方式和我想求的那一层。泛泛的「帮忙看看」对我没用，所以先把自己能给的都写清楚。

1. **A2 · 跨站点隔离怎么做最省事**：`allow-scripts + allow-same-origin` + `blob:` 继承父源，浏览器已实测告警 1 条。想要「主站与岛进程 ID 不同、控制台 0 条告警」。求：独立可注册域 / PSL 平台域 / 服务端代理，哪条路对这个体量的项目最现实？同 eTLD+1 的子域不算隔离，这点我已经知道了。
2. **A4 / A5 · 限流与上传扫描的参数**：写接口现在对 `anon` 开放。我在评估里暂定「写 10 次/分钟、上传 3 次/小时」，够不够？死循环、`top.location` 这类静态扫描怎么落地才不误伤正常作品？验收想把「1000 次压测被限流、恶意样本 6/6 被拦」当硬指标。
3. **A1 / C3 · 端点不进源码与错误码分层能否同时做**：后端地址目前内联在主页面（这是运行时必需的），而错误文案把四种故障压成一句。求：配置外置的边界应该划在哪、错误码怎么分层才不会把调试信息泄露给访客。
4. **B1 / B2 · 分页与正文缓存**：`fi_world` 全量返回，`fi_island_html` 返回全文（单件上限 2 MB）。双列游标 `(published_at, id)` 每页 24 条够不够？服务端要不要加一层缓存和大小闸门？
5. **B3 / B5 · 取景框在不做自由飞行的前提下能多壮阔**：坐标是按初始机位烘出来的构图参数，不是世界固定坐标；6356 行单文件、无模块无测试。**在保留随机洗牌、1 座活 iframe、点击飞过去、`0 style/s` 的前提下**，有没有低成本让画面更像「一片群岛」的做法？这一条我最想要具体建议，但不希望答案是「推倒重做成自由漫游」。
6. **B6 · 首屏压到 < 1 MB 的最小改法**：三座岛共享一份 three.js 会不会破坏「上传物必须自包含」这条硬约束？有没有不用改上传格式的办法？
7. **C2 / 托管 · 现在该不该迁自建后端**：额度耗尽自动暂停且暂停态不能导出，删应用还会连带删数据；现在零真实用户，是撤销代价最低的时点。求：是现在就迁，还是等真有人上传了再迁？
8. **邮件验证码 · 怎么验通又不污染正式数据**：本轮未做端到端实测。求一套能在不产生真实用户数据的前提下验证邮件链路的做法（本地桩 / 测试租户 / 白名单邮箱？）。

## 6. 服务器问题怎么解决

完整推导见 [`ASSESSMENT.md` 第三章](ASSESSMENT.md)，这里只写结论。

**现状的五个约束**（都是平台形态决定的，不是调配置能解决的）：

1. 单应用每月一份固定资源点，数据库、调用、存储、流量、验证码都从里面扣；**用尽后云服务自动暂停**，暂停期间数据既不能访问也不能导出，只保留有限天数。
2. 域名与后端 Origin 强绑定：重发必须复用同一个应用身份，换域名登录就失效；挂自有域名、上 CDN、配 WAF 都受限。
3. **不能单独关闭后端**，想释放名额只能删应用，而删除会永久删掉数据、文件和注册用户。
4. 预览和线上共用一套数据，测试写入会进正式库。
5. 表、函数、SDK 都围绕该平台设计，迁走时后端要重写。

**为什么非换不可**：这个产品的核心恰好是「让陌生人上传 HTML」，上传和注册是最耗额度、最容易被刷的两个行为，而额度耗尽的后果是整个服务暂停；再叠加 A2 / A4 / A5 的安全缺口，捆绑形态不适合开放注册。

**推荐路线（只有一条，A → B）**：

- 先把纯静态前端公开出来收集反馈（本仓库就是这一步），账号/上传/留言全关，零运维、零额度、零攻击面；
- 确认真有人要上传了，再按 **B 自建后端**：Node/Fastify 或 Go + PostgreSQL + 对象存储 + 独立的跨站点隔离域，自己管域名、证书、备份。目标形态是「静态前端 → HTTPS API → 鉴权/限流/扫描/审核 → 用户 HTML 放隔离域」。
- 独立 BaaS 项目只是折中对照，仍有额度与 Origin 绑定，不作为推荐。
- 评估里的原话是：**不要在还没有真实用户的时候就先背上一台服务器**。

**迁移检查单 7 步**：① 在云服务正常运行时导出全部数据（暂停态导不了）→ ② 选自有域名、配 HTTPS 与 CSP → ③ 用户 HTML 放隔离域、确认进程分离 → ④ `config.js` 只填自己后端的 publicConfig，真实值不进仓库 → ⑤ 补上 `server/schema.sql` 里缺的 `fi_island_add` 以及限流与审核（该文件 15 个函数，实际部署 16 个 RPC，有漂移）→ ⑥ 双跑观察 7 天，看错误率、上传成功率、单请求耗时、资源用量 → ⑦ 无误后下线旧应用，**且第 ① 步必须先做完**。

**成本与风险**：B 成本最高（服务器运维、监控、备份、证书、隔离域、审核人力），A 零运维但失去社区功能；具体金额我没有依据，不乱写。最大硬风险是「旧平台删应用会连带删数据」，所以导出必须先于下线。

**本轮边界**：只把方案写清楚。不建后端、不改 `config.js`（三个值继续全空、`FI_OFFLINE = true`）、不改 `server/schema.sql`、不动线上应用绑定、不删应用、不做数据导出、不申请域名、不产生任何真实用户数据。

## 7. 希望改进：做成大世界

先把话说死，免得被建议带偏：**这里的「大世界」是群岛增强，不是推倒重做**。下面 6 条是已经拍板、不打算改的方向：

1. 基准是云海大世界本身，**不是作品画廊列表**；
2. 同屏岛数不再锁 3 座，岛要散布成一片群岛；
3. 中心岛缩到约 317px（22%）；
4. **只有 1 座活 iframe**，其余体素岛；
5. 漫游是相机绕转 + 点击飞过去，**不做自由飞行**；
6. 「随机导屿」= 每次洗牌随机取景，**不是固定坐标世界**。

另外 **静止 `0 style/s` 是产品能否成立的分水岭，不是优化项**。所以：**不是**固定坐标世界、**不是**自由漫游、**不增加**活 iframe、**不做**每帧重排。

在这个前提下，我列了 8 个可做方向，**推荐先做前 3 个**（都是纯参数微调，不进布局高危区）：

| # | 方向 | 验收数字 |
|---|---|---|
| 1 | 岛数 `ISLE_COUNT` 11 → 13~14，同时校验 `MAX_VISIBLE` / `MAX_SLOT` | 1200 用例 0 重叠、最紧 ≥ 1.019、活 iframe 仍 1、静止 0 style/s |
| 2 | blob LRU 4 → 8 | 连续渡云 8 座不回源、内存 ≤ 16 MB 量级、静止 0 style/s 不变 |
| 3 | 云海/相机沉浸：云墙半径 22、雾密度、时辰配色、距离上下限、平移半径 | `dist=24.5` 不穿云墙、点击命中不劣化、帧率不下降、静止 0 写入 |

后 5 个（扩到 8 套构图模板、远景岛带、渡云拆成 200ms 淡出 + 400ms 淡入、LOD 密度、第二层云带）等 review 之后另开一轮。两条踩过的坑写在这里提醒自己：**任何 clamp 都会压平分布，把岛推远会让透视汇聚到画面中心**（分别造成过 2/1200 和 73/1200 重叠）；构图模板只允许镜像 + 小幅缩放，禁止翻转纵深符号或旋转坐标系。

**这一步还没落码**。岛数到底定几座我一直没拍板，等大佬给意见、我确认数值之后再单独开一轮；真落码时会按规矩升版本号并写完整变更记录。

## 8. 怎么复现 / 怎么参与

本仓库是纯静态、零构建，起个静态服务就行（**不要直接双击 `file://` 打开**，iframe 会变成不透明源，内置岛加载不了）：

```bash
python -m http.server 8000
```

| 参数 | 作用 |
|---|---|
| `?fill=1` | 补足 11 座展示群岛构图。**这些是示例副本，页面有角标标注，默认关闭，不是真实作品** |
| `?tod=0.5` | 固定时辰方便对图 |
| `?nointro=1` | 跳过入场动画 |
| `?perf=1` | 显示 fps / style/s / resize/s |

- GitHub：https://github.com/cbkkkkk/floating-isles
- Gitee：https://gitee.com/cao-bike/floating-isles
- 缺陷与优先级：[`ASSESSMENT.md`](ASSESSMENT.md)｜安全边界：[`../SECURITY.md`](../SECURITY.md)｜后端参考：[`../server/schema.sql`](../server/schema.sql)｜变更记录：[`../CHANGELOG.md`](../CHANGELOG.md)
