# 浮空岛 · 云海大世界

> *Cloud Isles — a shared sky world built from user-submitted HTML islands.*
>
> 一片云海，很多座岛。每座岛是一个独立的 HTML 作品，由创作者自己写成，再被放进同一个世界漂浮、被人串门。

## 这是什么

这不是一个 3D 建模器，也不是模板建站工具。它把「作品」直接定义成**一个单文件 HTML**：你想让岛上有什么，就自己写代码画出来。平台负责的是云海、光照、时辰、取景和把大家的岛摆到一起，不负责替你决定岛长什么样。

打开页面，你会看到一片会随时间变色的云海，若干座岛浮在上面。中心那座是当前焦点，其余是同批取景里的邻居。拖动可以绕着看，点远处一座岛会「渡云」飞过去把它变成新的焦点，右上角 `↻` 会重新洗一批岛。

这个仓库是**前端静态快照**：不含任何服务端地址、密钥、账号或个人信息，默认完全离线运行。

## 核心特性

- **云海大世界**：three.js r160 实时渲染，实体云、雾、昼夜十二时辰跟随本机时间
- **群岛取景**：同屏多座岛，中心焦点 + 周围邻居，焦点岛占屏宽约 22%
- **单文件 HTML 即作品**：上传物必须是自包含的 HTML，不能依赖外部资源
- **混合渲染**：只有焦点岛是活体 `iframe`（能交互），其余是 3D 体素岛（岩体 / 岛顶 / 方块 / 灯笼 + LOD）
- **随机导屿**：6 套构图模板 + 抖动洗牌，模板不连抽、避开最近 20 次出现过的岛
- **沙箱隔离**：他人作品降权到不透明源，父页面通过 `postMessage` 桥通信
- **零构建**：纯静态文件，无框架、无打包、无 npm 依赖，起个静态服务器就能跑

## 快速开始

**必须走 HTTP**，不能直接双击 `file://` 打开——`iframe` 在 `file://` 下会变成不透明源，内置岛加载不了。

```bash
# 在本仓库根目录执行（任选一种）
python -m http.server 8000
# 或 npx serve .
```

然后打开 `http://localhost:8000/`。

可选参数：

| 参数 | 作用 |
|---|---|
| `?fill=1` | 补足 11 座岛以展示群岛构图。**这些是示例副本，页面有角标标注，不是真实作品** |
| `?tod=0.5` | 把世界时辰固定在某一点，方便对图 |
| `?nointro=1` | 跳过入场动画 |

默认只显示仓库自带的 3 座内置岛（蓬莱仙境 / 古树 / 飞行堡垒），它们都是自包含 HTML，各自内联了渲染核心。

## 两种运行模式

| | 离线演示版（默认） | 接入后端 |
|---|---|---|
| 配置 | `config.js` 三个值留空 | 填入自己后端的 `endpoint` / `publishableKey` / `oauthRelayBaseUrl` |
| 网络请求 | **0**（`rpc()` 直接短路） | 走自己的后端 |
| 能看 | 云海、内置岛、随机导屿、点岛飞过去 | 同上 |
| 不可用 | 注册、上传、留言、点赞、私信 | 取决于后端实现 |
| 界面 | 隐藏账号/上传/私信入口，标注「离线演示版」 | 正常显示 |

`server/schema.sql` 给出了一套参考表结构（岛屿、留言、点赞、统计、私信、资料）和 15 个 `SECURITY DEFINER` 函数。**它只是迁移起点，不是可直接投产的后端**：缺少限流、审核、上传校验和邮件服务，详见 `docs/ASSESSMENT.md`。

## 技术栈与约束

- three.js r160，本地 UMD，无 CDN 依赖
- 原生 ES5 风格 JS，无模块打包、无框架、无构建步骤
- 静止时 `0 style/s`（iframe 定位带死区与尺寸量化，不做逐帧重排）
- 活体 iframe 同屏恒为 1 座；`blob:` URL 绝不拼查询参数（拼了会 404 白屏）
- 用户作品上限 2 MB、必须自包含、禁止外链资源
- 版本标识见 `index.html` 的 `fi-version` meta 与 `FI_VERSION` 常量

## 安全说明

本仓库**不含**任何真实服务端地址、访问密钥、分享码、邮箱、本机路径或账号标识；所有示例配置都是空值或占位符。离线模式不会发起任何跨域请求，也不会连接任何人的服务器。

但请注意：这个项目的核心功能就是**加载别人写的任意 HTML**，这件事本身有固有风险，当前实现并不完备。无头 Chromium 实载时会打印一条 `allow-scripts + allow-same-origin` 的沙箱逃逸告警——这是真实缺陷，已如实记录在 `SECURITY.md` 和 `docs/ASSESSMENT.md`。公开演示版不接收上传、不连后端，所以该路径没有入口，但**请勿把当前代码直接用于生产环境或开放注册**。

接入自己的后端前请先读 `docs/ASSESSMENT.md` 的 P0 清单。

## 现状与求助（求大佬看看）

一个人做到 `v3.1.3`，画面能跑，但注册链路、托管形态和内容安全这几件事判断不了了。作者把代码脱敏公开，**求大佬看看有什么问题**：[《现状与求助》](docs/现状与求助.md)。

里面有 8 个带编号、数字和复现步骤的具体问题（沙箱隔离 / 限流与上传扫描 / 错误码分层 / 分页与缓存 / 群岛增强 / 首屏体积 / 托管迁移 / 邮件验证），以及服务器方案与「做成大世界」的改进方向。本仓库是零网络请求的离线快照，不带任何真实端点或密钥。
